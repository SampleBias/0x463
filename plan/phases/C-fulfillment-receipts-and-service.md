# Phase C — Fulfillment, receipts, service, and CLI

Status target: four simulator scenarios from the CLI, receipts verified by a fresh process, buyer able to read the fixture.

Depends on: phase B gate.

Blocks: phase D.

## Goal

Add artifact transport, the deterministic verifier, durable coordinator state, audit events, timeout handling, receipt bundles, and the `settle463` CLI. The four required demos run against `settle463d` over loopback HTTP through the SDK.

4. T-ART-02 through T-ART-05, T-TIME-02 through T-TIME-05 on the simulator, T-IDEM-01 through T-IDEM-09, T-VER-01, T-VER-06, and T-VER-07 pass.

## WP-C1 — Verifier crate

`crates/settle463-verify` depends on `settle463-core` only.

`judge(artifact_bytes, policy, ledger_time, resolve_by) -> VerdictDraft` with these rules:

- If `ledger_time >= resolve_by`, return `INDETERMINATE` and `DEADLINE_EXPIRED`. Do not look at the bytes for a sticky decision.
- If the bytes cannot be obtained, the caller passes a transport error and the draft is `INDETERMINATE` / `UNAVAILABLE`.
- Otherwise evaluate size, UTF-8, duplicate keys, JSON shape, schema, and digest independently.
- Collect every matching failure code, sort them, and return `FAIL`.
- Return `PASS` / `MATCH` only when every check passes and the observations equal the policy.
- Never spawn a process, fetch a URL, or interpret the artifact as code.

`VerifierClient::judge` signs the draft. The first time a PASS or FAIL is stored for a delivery id, persist those exact signed bytes. A later call returns them and does not sign a second decision. `INDETERMINATE` is not stored as the definitive verdict.

The verifier key file is distinct from the buyer, seller, and coordinator keys. Tests assert the four public keys differ.

## WP-C2 — Artifact routes and ACLs

Implement the store rules in `02-api-persistence.md` inside `settle463d`.

- Files live under a configured root.
- Content ids are generated by the server.
- Path segments are checked hex.
- Seller upload uses the artifact preimage or a seller challenge.
- Buyer, seller, verifier, and receipt issuer can read. T-ART-04 uses a second order and expects `403`.
- Same digest re-upload returns the same content id (T-ART-05).
- The pass demo asserts the downloaded bytes equal the 52-byte fixture.

T-ART-02 is its own order. The committed policy digest is `a6c4530d161e5de02e365783fe7dbb96d93e6334ba78f0b52257e0b7fa75635a` and the length is `64`, for the extra-field bytes in `00-locked-decisions.md`. The schema remains the reference three-field schema. Expected verdict: `FAIL` including `SCHEMA_MISMATCH`, excluding `DIGEST_MISMATCH`.

Also reject the malformed, duplicate-key, and oversized fixtures (T-ART-03). Oversized may be a byte string of length `1048577` or a policy max that is lower. Do not allocate an unbounded buffer. Cap the HTTP body at 1048576 and treat a larger declared length as `OVERSIZED` without reading the rest.

## WP-C3 — Durable service

Implement migrations and the tables in `02-api-persistence.md`. Use SQLx migrations. Store `u64` amounts as decimal text.

Requirements:

- Acceptance insert and the order projection commit together.
- Intent insert and outbox insert commit together.
- Compare-and-set on `orders.version`.
- Idempotency behavior for T-IDEM-06, T-IDEM-07, and T-IDEM-08.
- Audit events carry `prev_digest` and a coordinator `observation` signature.
- Original signed bytes are stored and are what verification uses. Do not re-serialize from a struct and call that the original when the original bytes are available.

Challenge authentication matches the HTTP preimage in the API contract. A test signs a challenge and reads a private order, then repeats the challenge and receives `401`.

Direct exchange: `POST /v1/messages` accepts a signed quote or request, and `DirectPeer` in the SDK points at a second coordinator URL. One test sends a quote from seller to buyer without using the discovery list.

## WP-C4 — Timeouts and principal conservation

Extend the simulator backend with `commit_delivery`, `release`, and `refund` using the state table.

- Release requires a stored PASS verdict id and `now < resolve_by`.
- Refund from `Funded` requires `now >= deliver_by`.
- Refund from `Delivered` requires `now >= resolve_by`.
- FAIL does not move money and does not shorten the deadline.
- Replays return the known terminal result and transfer zero (T-IDEM-03, T-IDEM-05).
- Concurrent release and refund in tests use a barrier so both commands enter while the state is `Delivered` and the clock is still before `resolve_by` for one case, and at `resolve_by` for a case where only refund is legal. Where both are legal, exactly one terminal state wins and the invariant holds (T-IDEM-04). On the simulator, make the ledger operation atomic so the second command observes the terminal state.

Boundary tests use one fresh order per timestamp. Cover T-TIME-02, T-TIME-03, T-TIME-04, and T-TIME-05 on the simulator. T-TIME-01 already passed in phase B. Keep it passing.

## WP-C5 — Receipts

The coordinator signs a receipt only after the settlement backend reports a terminal finalized outcome. Simulator finality is `simulated-final` and is explicit in the ledger object.

Bundle shape is the JSON in `02-api-persistence.md`. Export tests:

- Pass bundle includes request, quote, acceptance, delivery, PASS verdict, receipt, and sim ledger.
- No-delivery bundle omits delivery and verdict and still verifies (T-VER-06).
- Verifier-offline bundle includes delivery, omits verdict, and verifies.
- A byte flipped in the bundle fails offline verification with exit 2 (T-VER-01).
- Wrong trusted issuer exits 3 (T-VER-07).
- Offline output contains `evidence_signed` and does not contain `ledger_verified`.

One receipt row per order. A retry of export returns the same signed receipt.

## WP-C6 — CLI demos

Implement `apps/settle463` with the commands in `02-api-persistence.md`.

`demo --backend sim` :

1. Creates a fresh deployment id `sim:` plus random lowercase hex, not `sim:fixture`.
2. Starts `settle463d` on `127.0.0.1` with a temporary SQLite file and artifact root.
3. Creates four fresh keys.
4. Drives discovery, request, quote, accept, fund, and the scenario steps through the HTTP SDK.
5. Prints the required stdout lines.
6. Writes the bundle and a trust file beside it. The trust file is not inside the bundle.
7. Stops the server.

Scenario behavior:

| Scenario | Extra steps |
| --- | --- |
| `pass` | Upload the 52 bytes, deliver, PASS, release before `resolve_by`. |
| `bad-artifact` | Upload the `units` `"4"` mutation, deliver, FAIL, advance clock to `resolve_by`, refund. |
| `no-delivery` | Do not upload or deliver. Advance clock to `deliver_by`. Refund. |
| `verifier-offline` | Upload the good bytes, deliver, do not start the verifier. Advance clock to `resolve_by`. Refund. |

Clock advances are simulator admin calls on the loopback service, gated by a test-only header or a local admin route that the binary enables only when `--backend sim` started that process. The route cannot move a Solana clock. Document it as a simulator control.

Integration tests in `tests/conformance/cli_sim.rs` or `apps/settle463/tests` invoke the binary with `assert_cmd` or a `std::process::Command`. They parse stdout. They then spawn `receipt verify` as a separate command.

`order inspect` reads the order through the public API and prints state and buckets.

## WP-C7 — Simulator crash recovery

T-REC-01 on the simulator:

1. Accept and prepare fund.
2. Commit the intent and outbox.
3. Stop the process before broadcast. A test hook in debug builds can exit after the commit when `SETTLE463_TEST_STOP=before_broadcast` is set. The hook is compiled only for test or debug, and it is documented. It must not skip signature checks.
4. Start a new process on the same database.
5. The worker broadcasts once.
6. Balances show one deposit. One order. No second debit if the worker runs twice.

## Evidence

## Stop conditions

- A demo calls a simulator method without HTTP while the gate requires the CLI path. Rework the demo.
- Receipt JSON contains the artifact body or a private key. Remove it.
- FAIL triggers an immediate payout or an immediate refund. Restore the deadline rule.
- Offline verify prints `ledger_verified`. Change the label.
