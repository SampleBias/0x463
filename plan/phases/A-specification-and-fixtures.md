# Phase A — Specification and fixtures

Status target: spec published, workspace compiling, golden vectors enforced.

Depends on: nothing.

Blocks: phases B through F.

## Goal

Publish the normative specification and a workspace that can detect a one-byte change in a signed message. An implementation other than the Rust crate reproduces the golden message id, order id, policy hash, and signature check.

## Entry

- Repository contains this `plan/` tree.
- No assumption that `spec/` or crates already exist. If a later rerun finds compatible files, keep them and fill gaps. Replace a file that contradicts a locked contract.

## Exit gate

All of the following are true:

1. `spec/` contains the documents listed in WP-A1, and their field names match `01-wire-contract.md`, `02-api-persistence.md`, and `04-solana-contract.md`.
2. `cargo test --locked -p settle463-core` passes, including T-GOLD-01 through T-GOLD-04 and T-WIRE-01.
3. `python3 fixtures/tools/independent_vector.py` exits 0 and prints the golden ids (T-GOLD-05).
4. A unit test mutates one canonical byte and fails verification (T-GOLD-02).
5. `cargo fmt --all --check` and `cargo clippy -p settle463-core --all-targets -- -D warnings` pass.
6. `build/phase-a-evidence.md` records the commands and the toolchain versions.

## Out of scope

HTTP service, CLI demos, artifact transport, simulator economy beyond types needed by the core, Anchor program, devnet.

## WP-A0 — Toolchain spike

Do this before writing crate code that depends on Solana.

1. Record `rustc --version`, `cargo --version`, `solana --version`, `anchor --version`, and `cargo-build-sbf --version` if present.
2. Choose a coherent Anchor and Solana pair using the rule in `00-locked-decisions.md`. Anchor 2.0.0 release candidates are excluded.
3. Generate a tiny Anchor program outside the final source tree, or in a scratch directory under `/tmp`, with one instruction that returns `Ok`.
4. Start `solana-test-validator`, deploy that program with the chosen CLI, and invoke the instruction.
5. On success, copy the version numbers into the pin files below. On failure, change both the Solana CLI and the Anchor version together and retry. Do not continue to WP-A2 with an unproven pair.
6. Write `spec/toolchain.md` with host Rust, platform-tools Rust, Solana CLI, Anchor CLI, `cargo-build-sbf`, and the SBPF architecture flag if one was required.

Create:

- `rust-toolchain.toml` pinning the host stable channel that passed the spike. Off-chain crates use this compiler.
- `Anchor.toml` at the workspace root with `toolchain` versions, `test_validator` startup, and a placeholder program id that phase D replaces after the first real deploy. Phase A may leave the program directory empty if the spike lived in `/tmp`. The pin file still exists.
- `rustfmt.toml` with `edition` set to the workspace edition.

The program compiler may differ from host `rustc`. That difference is a required sentence in `spec/toolchain.md`.

## WP-A3 — Canonical JSON and signatures

Implement in `settle463-core`:

1. A parser that rejects duplicate keys at every depth, invalid UTF-8, trailing bytes, numbers, and null.
2. A JCS serializer for the accepted subset (objects, arrays, strings, booleans) with UTF-16 key ordering and RFC 8785 string escaping.
3. Strict hex and decimal parsers with the limits in `01-wire-contract.md`.
4. Envelope validation for the eight closed kinds.
5. Preimage construction, strict Ed25519 verify, and message-id computation.
6. Order-id and policy-hash functions with the exact prefixes `0x463/order/0.1` and `0x463/policy/0.1`.

Kind body structs use the field names from the wire contract. Serde must not accept unknown fields. Duplicate-key rejection happens before Serde sees the value. A practical structure is a small recursive parser that builds a `serde_json::Value` only after the duplicate check, then a typed deserialize from that value.

Public functions, names adjustable but behavior fixed:

```text
parse_signed(bytes, expected_environment) -> SignedMessage
sign(unsigned, signing_key) -> SignedMessage
message_id(unsigned_canonical_preimage) -> [u8; 32]
order_id(environment, buyer, nonce) -> [u8; 32]
policy_hash(policy) -> [u8; 32]
```

`parse_signed` checks the signature, the issuer bytes, the version, the kind, and the expected environment.

## WP-A4 — Golden tests

1. Copy `plan/golden/positive-signing-vector.json` to `fixtures/golden/positive-signing-vector.json` without modification. `cmp` the two files in the evidence log.
2. `cargo test -p settle463-core --test golden` loads the fixture and recomputes canonical UTF-8, preimage hex, signature validity, message id, order id, and policy hash.
3. The mutation test flips the last canonical byte, or any one byte, and expects a different id and a failed verify.
4. The JCS test asserts the UTF-16 order hex from the golden file's `unicode_key_order` object. Also load `plan/golden/jcs-line-separators.json`. Canonicalize its escaped input and its decoded literal UTF-8 form, and require the stated bytes for both.
5. Write `fixtures/tools/independent_vector.py`. It uses Python's `hashlib` and `cryptography` (or OpenSSL `pkeyutl` for the verify step) and compares its output to the golden file. It does not call `cargo` and does not link the Rust library. Document the Python package in `fixtures/tools/README.md`. If `cryptography` is absent on a CI image, the script's verify step may call `openssl pkeyutl` and the hash step may stay on `hashlib`. Either path must be independent of `settle463-core`.

Negative wire tests cover the list in T-WIRE-01 plus a signature produced by a different secret.

## WP-A5 — CI skeleton

Add `.github/workflows/ci.yml` with one job, `domain`, that runs:

```text
cargo fmt --all --check
cargo clippy -p settle463-core --all-targets -- -D warnings
cargo test --locked -p settle463-core
python3 fixtures/tools/independent_vector.py
```

The job must not start a validator, contact a public RPC, or read a faucet. Later phases add jobs. They do not weaken this job.

## Evidence

Write `build/phase-a-evidence.md` with:

- Date and git revision.
- Toolchain table from `spec/toolchain.md`.
- Each command and its exit code.
- The golden message id, order id, and policy hash printed by the Python script.
- Statement that the Python or OpenSSL check does not call the Rust crate.

## Stop conditions

- The spike cannot deploy a program to a local validator. Stop and record the incompatibility. Do not invent a pin.
- Golden recomputation disagrees with `plan/golden/positive-signing-vector.json`. Fix the Rust parser. Do not edit the golden file to match a buggy serializer.
- A dependency pulls Solana into `settle463-core`. Remove it before the gate.

## Handoff

Phase B may import `settle463-core` types for offers, requests, quotes, acceptances, ids, and signature verification. It may rely on the published `spec/api-v1.md` even though the HTTP server does not exist yet.
